Installation guide

D2HA runs on any amd64 or arm64 machine with Docker Engine 24 or newer. We recommend the Compose setup: it includes a Docker socket proxy with secure defaults.

Docker Compose Recommended

Copy compose.example.yaml to a new folder as compose.yaml, read it, then:

docker compose up -d
docker logs d2ha   # ← your one-time setup code

The example starts two containers: d2ha, published on 127.0.0.1:12021 only, and docker-proxy, so D2HA never touches the Docker socket directly and can only make the API calls it needs.

Docker Run Quick test

Good for a quick look, without the socket proxy.

docker run -d \
  --name d2ha \
  -p 127.0.0.1:12021:12021 \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  -v $(pwd)/data:/app/data \
  ghcr.io/arborae/docker2homeassistant:latest
First run

The container log shows a one-time setup code. Open http://localhost:12021, enter the code and create your account — there are no default credentials. On a server without a browser, open an SSH tunnel first (ssh -L 12021:localhost:12021 <user>@<server>), then that address works on your computer.

Two-factor authentication (TOTP) is available in Settings → Account and security, and recommended if D2HA is reachable through a reverse proxy or a tunnel.

Home Assistant

From Home Assistant 2026.11: open Settings → Marketplace → Add from link, enter github.com/arborae/ha-d2ha with type Integration (the first time, the Marketplace asks you to connect GitHub), then Install and Restart Home Assistant. On Home Assistant 2026.8 to 2026.10, add the same address in HACS as a custom repository of type Integration, download D2HA and restart. The integration requires Home Assistant 2026.8 or later. This link opens the repository page for you, in the Marketplace or in HACS.

Then create an API token in D2HA under Settings → Home Assistant and add the integration in Home Assistant with the address of D2HA and the token.

Configuration tips

Everything is optional; the full list is in .env.example:

D2HA_CHECK_INTERVAL_HOURS — hours between update checks (6 by default)
D2HA_GITHUB_TOKEN — raises the GitHub rate limit for release notes
D2HA_TELEGRAM_TOKEN + D2HA_TELEGRAM_CHAT_ID — Telegram notifications
D2HA_READ_ONLY — notifications and logs only, no updates
D2HA_FRAME_ANCESTORS — allow a Home Assistant dashboard to embed D2HA

Prefer living on the edge? The :nightly image tag ships the latest features — potentially unstable.

Keep it private

D2HA can update containers, so treat it like an admin panel: keep it off the internet, or put it behind HTTPS and an access layer (a VPN, Cloudflare Access, an authenticating reverse proxy).

The example compose binds to 127.0.0.1 on purpose: a reverse proxy or tunnel on the same machine can reach it, the rest of the network cannot.
